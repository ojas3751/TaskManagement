# API設計 v1.1

**関連文書**: [要件定義書](../requirements.md) ／ [機能仕様書](../functional-spec.md) ／ [データベース設計](database.md) ／ [文書一覧](../README.md)

バックエンドが提供するエンドポイントの一覧。**詳細な入出力仕様（リクエスト・レスポンスの構造）は、技術スタック確定後に本書へ追記する。**

認証は対象外のため、認証関連のエンドポイントは存在しない。

> **本文では「タスク」と書き、パスは `/api/cards` のままとする。** この対応は意図的なもの。理由は [要件定義書](../requirements.md) の「用語」を参照。

## 1. エンドポイント一覧

| メソッド | パス | 内容 | 関連機能 |
| --- | --- | --- | --- |
| GET | `/api/board` | ボード・リスト・タスクを**一括取得**（初期表示用） | F-01 |
| POST | `/api/lists` | リストの追加（完了の左隣に挿入） | F-02 |
| PATCH | `/api/lists/:id` | リスト名の変更 | F-03 |
| DELETE | `/api/lists/:id` | リストの削除（内部のタスクも削除） | F-04 |
| PATCH | `/api/lists/reorder` | リストの並び替え（再採番結果を一括送信） | F-05 |
| POST | `/api/cards` | **タスクの追加（先頭）。再採番結果を一括送信する** | F-06 |
| PATCH | `/api/cards/:id` | タスクの編集（タイトル・説明文・期限） | F-07, F-09 |
| DELETE | `/api/cards/:id` | タスクの削除 | F-08 |
| PATCH | `/api/cards/move` | タスクの移動（移動先リストと再採番結果を一括送信） | F-12, F-13 |
| POST | `/api/cards/bulk-delete` | 完了列での選択削除 | F-15 |

> **`POST /api/cards` は先頭追加になったため、再採番を伴う。** 当初は末尾追加で `max(position) + 1` を振るだけだったが、追加位置の変更（[機能仕様書](../functional-spec.md) の「タスクの追加位置」）により、対象リスト内の既存タスクの `position` をずらす必要がある。したがって下記 2.1 のトランザクション要件が、このエンドポイントにも適用される。

## 2. 設計方針

### 2.1 再採番はトランザクションで完結させる

**再採番を伴う更新は1リクエスト・1トランザクションで完結させる。** 複数リクエストに分けると、途中で失敗した場合に並び順が壊れるため。

対象は `PATCH /api/lists/reorder`、`PATCH /api/cards/move`、**`POST /api/cards`** の3つ。いずれも「変更後の並び順すべて」をまとめて送る。

### 2.2 初期表示は1リクエストで取得する

`GET /api/board` はボード・リスト・タスクをまとめて返す。リストごとにタスクを取得する作りにすると、リクエスト数が列数に比例して増える（N+1 問題）。

### 2.3 入力値の検証はサーバー側で必ず行う

画面側の入力制限は迂回できるため、**API は単独で呼ばれても不正なデータを受け付けない**ことを保証する。検証対象は以下。

| 対象 | 内容 |
| --- | --- |
| タイトル | 空文字でないこと、100文字以内 |
| 説明文 | 5,000文字以内 |
| リスト名 | 空文字でないこと、50文字以内 |
| 件数 | リスト20件以内、1リストあたりタスク200件以内（`COUNT(*)` で判定） |
| リストの保護 | `is_default` が true のリストは改名・削除を拒否する |
| リストの位置 | `is_fixed_last` が true のリストは移動を拒否する。また他のリストを最右へ移動させない |

### 2.4 エラー応答

| 状況 | ステータス | 画面側の扱い |
| --- | --- | --- |
| 入力値が不正 | 4xx＋不正内容のメッセージ | 何が不正かを表示 |
| DB に接続できない | 5xx | 「Docker が起動しているか確認してください」 |
| サーバー自体が停止 | 応答なし（リクエスト失敗） | 「サーバーが起動していません」 |

画面側の挙動は [機能仕様書](../functional-spec.md) の「誤操作・エラーへの対策」を参照。
