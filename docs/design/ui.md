# 画面設計 v1.8

**関連文書**: [要件定義書](../requirements.md) ／ [機能仕様書](../functional-spec.md) ／ [文書一覧](../README.md)

**画面はボード画面1つのみ。** 認証を対象外としたため、ログイン画面は存在しない。

本書の図は**ワイヤーフレーム相当**であり、**要素の有無と配置を示すもの**。寸法・余白・書体・具体的な配色は含まない（[要件定義書](../requirements.md) の「未決定事項」のとおり未定）。

> **本書では「タスク」と書く。** DBのテーブル名とAPIのパスは `cards` のままであり、これは意図的な使い分け（[要件定義書](../requirements.md) の「用語」を参照）。
>
> **タスクに移動ボタンは付けない。** 移動はドラッグ&ドロップ（F-13）と詳細モーダルのリスト選択欄（F-23）で行う。

## 1. ボード画面（全体）

```
┌──────────────────────────────────────────────────────────────────────┐
│  マイタスク                                                           │
├──────────────┬──────────────┬──────────────┬────────────────────────┤
│ [←]      [→] │ [←]      [→] │ [←]      [→] │                        │
│     TODO     │    進行中     │    ✎ 設計    │ 完了                   │
│ [+ タスク追加]│ [+ タスク追加]│ [+ タスク追加]│ [+ タスク追加]         │
│ ┏━━━━━━━━━━┓ │ ┌──────────┐ │              │  ┌──────────────────┐ │
│ ┃ 請求書送付 ┃ │ │ 資料作成  │ │              │  │ 打合せ    08/01   │ │
│ ┃ 08/10 09:00┃ │ │ 08/15    │ │ （タスクなし）│  └──────────────────┘ │
│ ┗━━━━━━━━━━┛ │ └──────────┘ │              │  ┌──────────────────┐ │
│ ┏━━━━━━━━━━┓ │              │              │  │ 見積提出          │ │
│ ┃ 買い物      ┃ │              │              │  └──────────────────┘ │
│ ┃ 08/16      ┃ │              │              │      ：                │
│ ┗━━━━━━━━━━┛ │              │              │   （入りきらない分は    │
│              │              │              │     この領域内で        │
│              │              │              │     スクロール）        │
└──────────────┴──────────────┴──────────────┴────────────────────────┘
        ↑ 盤面の下端はウィンドウの下端。ページ全体は縦にスクロールしない
                                        [+ リスト追加]
                                     （「完了」の左隣に挿入される）
```

**「完了」列は、ホバーまたはフォーカスでチェックボックスが現れる（F-15）。**

```
  通常（何も選んでいない）        ホバー中 ／ 選択済み
 ┌────────────────────┐        ┌────────────────────┐
 │ 完了                │        │ 完了                │
 │ [+ タスク追加]      │        │[全選択][選択解除][2件を削除]│
 │  ┌──────────────┐  │        │ ☑ ┌──────────────┐ │
 │  │ 打合せ  08/01│  │  ───▶  │   │ 打合せ  08/01│ │
 │  └──────────────┘  │        │   └──────────────┘ │
 │  ┌──────────────┐  │        │ ☐ ┌──────────────┐ │
 │  │ 見積提出      │  │        │   │ 見積提出      │ │
 │  └──────────────┘  │        │   └──────────────┘ │
 └────────────────────┘        └────────────────────┘
   カードは中央。左右に               カードが右へ 12px 寄り、
   20px ずつ空いている                空いた左にチェックが出る
```

| 要素 | 補足 |
| --- | --- |
| **`[←] [→]`** | 列の並び替え（F-05）。**リスト名の上の行**に置き、両端に寄せる。「完了」には表示しないが、**その行の高さは空ける**（出し分けで高さが変わると、完了列だけタスクの開始位置がずれる）。**左端の列の `[←]` と、完了の左隣の列の `[→]` は押せない状態で残す**（消すと列によってボタンの数が変わり、見出しの位置がずれる）。**列については残す**（代替手段の F-21 が MVP に無いため） |
| **`✎`（編集アイコン）** | **リストの詳細モーダル（6章）を開く。** 改名（F-03）も削除（F-04）もその中で行う。**追加した列にのみ表示**し、デフォルト3列には出さない。**リスト名の左端**に置く |
| **リスト名** | **1行に固定し、折り返さない。** 列幅に収まらない分は**末尾を `…` で省略**する。**マウスでホバーするとフルネームを出す**（`title`）。**見た目はブラウザと OS が決めるため指定しない**（大きさを変えるには自前で描くことになり、仕組みごとの置き換えになる）。**キーボードで見えるようにはしない** — 全文は編集アイコンの読み上げ名と、そこから開くモーダルの入力欄で読める。そのためだけにツールチップを作ると、**列ごとに Tab の停留点が1つ増え**、タスクへ辿り着くまでの操作が列数ぶん長くなる |
| **`[+ タスク追加]`** | **列の最上部。** 押して入力すると、**すぐ下（列の先頭）**にタスクが入る（F-06）。「完了」列で1件以上選択されている間は、この位置が選択の行に**入れ替わる** |
| **タスクの移動ボタン** | **存在しない。** 移動はドラッグ&ドロップ（F-13）と詳細モーダル（F-23）で行う。F-12 は欠番 |
| `☐` チェックボックス | **「完了」列のタスクにのみ**（F-15）。**普段はカードの下に隠れており**、ホバーまたはフォーカスで現れる。**チェックした行は、ホバーを外しても出たまま**になる |
| **選択の行** | `[全選択] [選択解除] [〇件を削除]` の3つを1行に。**1件以上選ばれているときだけ**、`[+ タスク追加]` と入れ替えて出す。**枠と余白は `[+ タスク追加]` と同じ**にすること |
| （タスクなし） | **空状態。** タスクが0件の列に表示する。**ここにもドロップできる** |
| `：` | 図の省略記号（実際の画面には表示しない） |
| **タスク一覧の領域** | **列の中で縦にスクロールする**（F-25）。スクロールするのはここだけで、`[← リスト名 →]` と `[+ タスク追加]`（＝選択の行）は**外に置くため隠れない**。**横にはスクロールさせない。** 縦のスクロールバーは細くする |
| **列とカードの幅** | 列は **300px（全列共通）**、カードは **240px 固定で中央寄せ**。左右に 20px ずつ空き、これがチェックボックスの寄り代になる |
| `[削除]`（タスク） | **図では省略している。出し方は未決定**（常時表示・ホバー時のみ・詳細モーダル内へ移動）。移動ボタンが無くても削除ボタンが常時表示では閲覧性の問題が半分しか解決しないため、実物を見て決める |

> **盤面はウィンドウの高さに収める。**（F-25）**ページ全体が縦にスクロールすると、ボード名もリスト名も一緒に流れて隠れる。** 列が多いボードでは、どの列に入れようとしているかが分からなくなる。スクロールする範囲を各列のタスク一覧だけに絞れば、見出しは常に見えたままになる。
>
> **リスト名を `position: sticky` で貼り付ける方法は採らない。** 見出しをスクロール領域の外の兄弟要素として置けば、貼り付ける必要がそもそも無い。
>
> **表示件数の上限は設けない。** 見える件数はウィンドウの高さ次第。以前は「9件まで表示し、10件目が上部だけ覗く」（F-14）としていたが取り下げた。経緯は [要件定義書](../requirements.md) の「機能一覧」を参照。

> **チェックボックスを常時表示にしない理由。**（F-15）常に出すと、その幅のぶん**完了列だけカードが狭くなるか、列の幅が他と揃わなくなる。** この画面は列を横に見比べるためのものなので、完了列だけ見た目が変わるのは避けたい。**普段は隠しておき、ホバーかフォーカスで出す。**
>
> **カードは動かさず、と最初は考えたが、場所が足りなかった。** カードの左に空いているのは余白だけで、そこへチェックボックスを出すと列からはみ出す。**カードを右へ 12px 寄せて、空いた左に出す。**
>
> **寄ること自体も選択の合図として使う。** チェックの印だけでなく行の位置でも示すので、**別のウィンドウが重なって見づらいときでも、選ばれている行が分かる。** 複数のウィンドウを開いて重なっている状況は容易に起こりうる。
>
> **ホバーを判定する対象は、動かない外側の入れ物にする。** カードを対象にすると、右へ寄った瞬間にポインタがカードの外に出て判定が切れ、戻ってまた寄る、を繰り返して振動する。
>
> **チェックボックスは列の左端に貼り付けない。** フォーカスの枠はチェックボックスの外側に描かれるため、左端に置くと枠がスクロール領域に切り取られ、**フォーカスが当たっているのに見えない**状態になる。
>
> **選択の行は `[+ タスク追加]` と入れ替える（足さない）。** 行を増やすと完了列だけタスクの先頭が1行ぶん下がり、横に並べたときに揃わなくなる（v1.4 の編集アイコン、v1.6 の並び替えの行と同じ理由）。**入れ替える相手と枠・余白を揃えないと、チェックを入れた瞬間に列の中身が上下してがたつく。**
>
> **1件も選んでいないと選択の行は出ない。** 全件削除が確認モーダル1枚で到達できるより、**まず1件チェックさせる方が誤操作を抑えられる。** そのぶん、まとめて消せること自体はホバーするまで気づけない。

> **`[+ タスク追加]` を最上部に置く理由。** 追加ボタンが上端にあるのに追加物が末尾に現れると、追加したものが視界の外に出る。**タスクが入りきらない列ではスクロールしないと確認できず**、登録できたか分からない。**操作した位置と、結果が現れる位置を一致させる。**
>
> **タスクに移動ボタンを置かない理由。** ボタンが件数分だけ縦に積み上がると、1件あたりの高さが増えて**1画面に収まるタスクが減る**。一覧して状況を把握することがボードの主目的である以上、そこを削ってまで操作手段を増やさない（[機能仕様書](../functional-spec.md) の「タスクの移動・並び替え」を参照）。

## 2. タスク（拡大）

```
 ┏━━━━━━━━━━━━━━━━━━━━┓  ← 期限による色付きボーダー（F-11）
 ┃ 請求書送付            ┃  ← タイトル（クリックで詳細モーダル）
 ┃ 08/10 09:00      [🗑] ┃  ← 期限とゴミ箱を同じ行に。ゴミ箱は右端
 ┗━━━━━━━━━━━━━━━━━━━━┛     掴んでドラッグすると移動する

 期限がない場合も行の高さは変えない
 ┏━━━━━━━━━━━━━━━━━━━━┓
 ┃ 読みたい本を探す      ┃
 ┃                  [🗑] ┃  ← 期限の位置は空けたまま
 ┗━━━━━━━━━━━━━━━━━━━━┛
```

一覧に表示するのは**タイトルと期限のみ**。説明文は表示しない。

| 要素 | 補足 |
| --- | --- |
| ゴミ箱アイコン | **削除（F-08）。** 「削除」の文字ボタンにはしない。**常時表示**とし、ホバー時のみにはしない |
| 配置 | **期限と同じ行の右端。** 削除のためだけに行を増やさない |
| 色 | **タスクの文字色に追従させる。** 期限超過・当日（白文字）でも完了列（黒文字）でも判別できること |
| 期限なしの場合 | **行の高さは揃える。** 期限の有無で高さが変わると縦の並びがばらつく |

> **アイコンは実装側の図形描画で作る。** 画像ファイルは持たない。絵文字（🗑）も使わない — フォントによって字形も色も変わり、文字色への追従ができないため。**上図の `🗑` は図中での便宜的な表記**であり、実装に絵文字を使う意味ではない。

## 3. ドラッグ中の表示（F-13）

**どこに落ちるかを、指を離す前に分かるようにする。** 落ちた場所が予想と違うと、利用者は毎回結果を確認してからやり直すことになる。

```
   移動元                        移動先（「進行中」列）
 ┌──────────────┐            ┌──────────────┐
 │ [+ タスク追加]│            │ [+ タスク追加]│
 │ ┌──────────┐ │            │ ┌──────────┐ │
 │ │ 資料作成  │ │            │ │ 資料作成  │ │
 │ └──────────┘ │            │ └──────────┘ │
 │              │            │ ━━━━━━━━━━━━ │ ← 挿入位置を示す線
 │              │ …掴まれた   │ ┌──────────┐ │
 │              │   元の位置  │ │ 打合せ    │ │
 │              │  （空ける） │ └──────────┘ │
 └──────────────┘            └──────────────┘

                  ┏━━━━━━━━━━┓
                  ┃ 請求書送付 ┃ ← ポインタに追従する本体
                  ┃ 08/10 09:00┃
                  ┗━━━━━━━━━━┛
```

| 要素 | 仕様 |
| --- | --- |
| 掴まれたタスクの元の位置 | **透明にして場所だけ残す。** カードは描かないが、幅も高さもそのまま空ける |
| ポインタに追従する本体 | 掴んでいるタスクの見た目を保つ。**盤面の外側に描き、列のスクロール領域には切り取らせない** |
| **挿入位置の線** | ポインタのY座標が、どのタスクの前後に入るかを示す。**列をまたいでも同様に出す** |
| 落ちる位置以外の見せ方 | **他のカードは動かさない。** 落ち先は線だけで示す |
| 空状態の列 | 「（タスクなし）」の領域全体が受け口になる |
| スクロールする列 | **スクロール位置はそのままドロップを受け付ける。** 落としたい位置が見えていない場合は、**掴む前にその列をスクロールしておく**（F-25）。ドラッグ中に端で自動スクロールする仕組みは持たない |
| ドロップ範囲の外で離した場合 | 移動しない。元の位置に戻る |

> **掴まれた元の位置を、薄く残すのではなく透明にした理由。**（2026-08-30、#78）
> v1.8 までは「薄く表示し、まだそこに属していることを示す」としていた。実装して触ったところ、**ポインタに追従する本体と同じカードが2枚見える**状態になり、目は動いている本体の方を追うため、薄い方が情報として働いていなかった。
>
> **消さずに場所を空けるのが要点。** 消すと並びが詰まり、掴んだ瞬間に列全体が動く。透明なら幅も高さもそのままなので、空いた場所が「ここから出ていく」という予約として読める。

> **落ち先を線だけで示す理由。**（2026-08-30、#78）
> 「他のカードが動いて隙間が空く」見せ方と併用しない。**示し方が二重になって読みにくい**うえ、**列をまたぐと隙間は原理的に出ない**（並び替えの範囲が列ごとに別々のため）。線に一本化すれば、同じ列でも別の列でも見え方が揃う。
>
> **落ち先はポインタのY座標で決める**（この表の「挿入位置の線」のとおり）。カードの中線より上ならそのカードの手前、どの中線にも届かなければ末尾。**ライブラリが持つ距離ベースの判定は使わない** — 受け口の重心や四隅との近さで選ぶため、列と列の間の余白でいちばん近い列が選ばれ、カードとカードの隙間では列そのものが選ばれて末尾へ飛ぶ。
>
> **キーボード操作のときだけ距離で決める。** 掴んで矢印で動かす操作にポインタは存在しないため。線はどちらの操作でも出る。

## 4. タスクの詳細モーダル（F-07, F-23）

タスクのタイトル部分をクリックすると開く。

```
      ┌────────────────────────────────────────────┐
      │ タスクの詳細                          [ ✕ ] │
      ├────────────────────────────────────────────┤
      │ リスト                                      │
      │ ┌──────────────────┐                       │
      │ │ TODO           ▼ │                       │  ← 移動先を選ぶ（F-23）
      │ └──────────────────┘                       │
      │                                            │
      │ タイトル                                    │
      │ ┌────────────────────────────────────────┐ │
      │ │ 請求書送付                              │ │
      │ └────────────────────────────────────────┘ │
      │                                      5/100 │  ← 文字数カウンタ
      │                                            │
      │ 説明文                                      │
      │ ┌────────────────────────────────────────┐ │
      │ │ 8月分の請求書をまとめて送付する。        │ │
      │ │                                        │ │  ← 改行を保持
      │ │ ・A社                                   │ │
      │ │ ・B社                                   │ │
      │ │                                        │ │
      │ └────────────────────────────────────────┘ │
      │                                   348/5000 │
      │                                            │
      │ 期限                                        │
      │ ┌──────────────┐  ┌──────────┐            │
      │ │ 2026/08/10   │  │  09:00   │            │
      │ └──────────────┘  └──────────┘            │
      │ [ 期限をクリア ]   ☑ 時刻を指定する         │
      │                                            │
      ├────────────────────────────────────────────┤
      │                    [ キャンセル ] [ 保存 ] │
      └────────────────────────────────────────────┘
```

| 要素 | 補足 |
| --- | --- |
| **`リスト` の選択欄** | **F-23。** 現在の所属リストを表示し、変更して `[ 保存 ]` すると**そのリストの末尾へ移動する**。選択肢は「完了」を含む全リスト |
| 文字数カウンタ | 入力欄の右下。上限到達で赤 |
| `☑ 時刻を指定する` | **`cards.has_due_time` に対応。** 外すと時分の入力欄が無効になり、表示からも時分が消える |
| `[ 期限をクリア ]` | `due_at` を NULL に戻す（期限なし） |
| 閉じ方 | `[ ✕ ]`、`[ キャンセル ]`、背景クリックのいずれか |

> **リストの選択欄をタイトルより上に置く理由。** そのタスクが「今どこにあるか」は、内容を読む前に把握したい情報だから。また **`[ 保存 ]` までキーボードのタブ移動だけで到達できる位置**にあることで、マウスを使わない移動操作（F-23 の主目的）が自然な順序になる。

## 6. リストの詳細モーダル（F-03, F-04）

**リストの編集アイコン（1章）から開く。** リスト名の変更と削除をここで行う。

```
      ┌────────────────────────────────────┐
      │ リストの詳細                  [ ✕ ] │
      ├────────────────────────────────────┤
      │ リスト名                            │
      │ ┌────────────────────────────────┐ │
      │ │ 設計・調査                      │ │  ← 現在の名前が入った状態で開く
      │ └────────────────────────────────┘ │
      │                              5/50  │  ← 文字数カウンタ（E-01）
      ├────────────────────────────────────┤
      │ [ このリストを削除 ]                │  ← 赤系。押すと確認モーダル（7章）
      │ 中のタスク 3 件も一緒に削除されます。│
      ├────────────────────────────────────┤
      │            [ キャンセル ] [ 保存 ] │
      └────────────────────────────────────┘
```

| 要素 | 補足 |
| --- | --- |
| リスト名 | **現在の名前が入った状態**で開く。付け直しではなく手直しになるため。上限50文字 |
| `[ このリストを削除 ]` | **保存とは別の区画に置く。** 並べると押し間違える。押すと確認モーダル（7章）へ進む |
| 件数の注記 | **確認モーダルを開く前に、何が失われるかを見せる** |
| デフォルト3列 | **そもそも開けない**（編集アイコンを出さない）。サーバーも改名・削除を拒否する |

> **「リスト名の変更」専用のモーダルにしない理由。** 名前1つのためだけのモーダルは操作に対して重く、**使っているうちにその場編集へ寄せたくなり、モーダルごと無くなる。** 一方、リストに対する操作は名前だけではない（削除がある）。**対象を開いて、その状態をまとめて扱う**形にすれば、タスクの詳細モーダル（4章）と作法が揃う。
>
> **削除をこの中に置く理由。** 列の削除は**滅多にやらず、中のタスクごと消える**。列見出しの行にゴミ箱を並べると、滅多に使わないものが常に目に入り、押しやすい位置に居座る。**ひと手間奥に置く方がこの操作に合う。**
>
> **タスクの削除がカード上にある（2章）のとは非対称だが、意図的。** タスクの削除は**日常的で件数が多く**、リストの削除は**稀で影響が大きい。** 頻度と危険度が逆なので、置き場所が違ってよい。
>
> **置き場所ができたことを理由に機能を足さない。** ここに置くのは、リストそのものの状態に関わるものだけ。

## 7. 削除の確認モーダル（F-04, F-08, F-15）

```
      ┌────────────────────────────────────┐
      │ 削除の確認                          │
      ├────────────────────────────────────┤
      │ リスト「設計」を削除します。        │
      │ 中のタスク 3 件も一緒に削除されます。│
      │ この操作は取り消せません。          │
      ├────────────────────────────────────┤
      │          [ キャンセル ] [ 削除する ]│
      └────────────────────────────────────┘
              ↑ 初期フォーカス      ↑ 赤系
```

| 操作 | 文言に含めるもの |
| --- | --- |
| タスクの削除（F-08） | タスク名 |
| リストの削除（F-04） | リスト名 ＋ **道連れになるタスクの件数** |
| 完了列の選択削除（F-15） | 選択件数 |

いずれも「この操作は取り消せません」を添える（Undo は対象外のため）。

> **初期フォーカスは「キャンセル」に置く。** 開いた直後に `Enter` を押しても削除されないようにするため。

```

└──────────────┴──────────────┴──────────────┴─────────────────────┘
```
