# 画面設計 v1.17

**関連文書**: [要件定義書](../requirements.md) ／ [機能仕様書](../functional-spec.md) ／ [文書一覧](../README.md)

**画面はボード画面1つのみ。** 認証を対象外としたため、ログイン画面は存在しない。

本書の図は**ワイヤーフレーム相当**であり、**要素の有無と配置を示すもの**。寸法・余白・書体・具体的な配色は含まない（[要件定義書](../requirements.md) の「未決定事項」のとおり未定）。

> **本書では「タスク」と書く。** DBのテーブル名とAPIのパスは `cards` のままであり、これは意図的な使い分け（[要件定義書](../requirements.md) の「用語」を参照）。
>
> **タスクに移動ボタンは付けない。** 移動はドラッグ&ドロップ（F-13）と詳細モーダルのリスト選択欄（F-23）で行う。

## 1. ボード画面（全体）

### 1.1 平常時（編集モードの外）

**リストへの操作は何も出さない。**

```
┌──────────────────────────────────────────────────────────────────────┐
│  マイタスク            [ リストを編集する ]                            │
├──────────────┬──────────────┬──────────────┬────────────────────────┤
│     TODO     │    進行中     │     設計      │ 完了                   │
│ [+ タスク追加]│ [+ タスク追加]│ [+ タスク追加]│[全選択][選択解除][0件を削除]│
│ ┏━━━━━━━━━━┓ │ ┌──────────┐ │              │  ┌──────────────────┐ │
│ ┃ 請求書送付 ┃ │ │ 資料作成  │ │              │  │ 打合せ    08/01   │ │
│ ┃ 08/10 09:00┃ │ │ 08/15    │ │ （タスクなし）│  └──────────────────┘ │
│ ┗━━━━━━━━━━┛ │ └──────────┘ │              │  ┌──────────────────┐ │
│ ┏━━━━━━━━━━┓ │              │              │  │ 見積提出          │ │
│ ┃ 買い物      ┃ │              │              │  └──────────────────┘ │
│ ┃ 08/16      ┃ │              │              │      ：                │
│ ┗━━━━━━━━━━┛ │              │              │   （入りきらない分は    │
│              │              │              │     この領域内で        │
│              │              │              │     スクロール）        │
└──────────────┴──────────────┴──────────────┴────────────────────────┘
        ↑ 盤面の下端はウィンドウの下端。ページ全体は縦にスクロールしない
```

> **`[←] [→]`・編集アイコン（✎）・`[+ リスト追加]` は、この状態では出さない。**（#89）**リストへの操作はすべて 1.2 の編集モードの中にある。** 平常時の盤面に出るのは**リスト名とタスクだけ**で、列の最上部に矢印のための行も取らない。

**どの列も、ホバーまたはフォーカスでチェックボックスが現れる。** 出し方は同じで、**意味だけが違う** — 「完了」列では**選択**（F-15）、それ以外の列では**「完了にする」**（F-22）。

```
  「完了」以外の列（F-22）
 ┌────────────────────┐
 │ TODO                │
 │ [+ タスク追加]      │
 │  ┌──────────────┐  │      ☐ を押すと、このタスクが
 │  │ 請求書   08/10│  │ ───▶ 「完了」列の先頭へ移る
 │  └──────────────┘  │      （チェックは入ったままにならない）
 │ ☐ ┌──────────────┐ │
 │   │ 買い物   08/16│ │
 │   └──────────────┘ │
 └────────────────────┘
   ホバー中の行だけカードが
   右へ 12px 寄る
```

**「完了」列では、同じチェックボックスが「選択」を意味する（F-15）。**

```
  通常（何も選んでいない）        ホバー中 ／ 選択済み
 ┌────────────────────┐        ┌────────────────────┐
 │ 完了                │        │ 完了                │
 │[全選択][選択解除][0件を削除]│        │[全選択][選択解除][2件を削除]│
 │  ┌──────────────┐  │        │ ☑ ┌──────────────┐ │
 │  │ 打合せ  08/01│  │  ───▶  │   │ 打合せ  08/01│ │
 │  └──────────────┘  │        │   └──────────────┘ │
 │  ┌──────────────┐  │        │ ☐ ┌──────────────┐ │
 │  │ 見積提出      │  │        │   │ 見積提出      │ │
 │  └──────────────┘  │        │   └──────────────┘ │
 └────────────────────┘        └────────────────────┘
   選択の行は出ているが、             カードが右へ 12px 寄り、
   [選択解除][0件を削除] は          空いた左にチェックが出る
   押せない。カードは中央で
   左右に 20px ずつ空いている
```

| 要素 | 補足 |
| --- | --- |
| **`[←] [→]`** | 列の並び替え（F-05）。**編集モード中にだけ、リスト名と同じ行に出す**（1.2）。「完了」には出さない。**左端の列の `[←]` と、完了の左隣の列の `[→]` は押せない状態で残す**（消すと列によってボタンの数が変わり、見出しの位置がずれる） |
| **`✎`（編集アイコン）** | **リストの詳細モーダル（6章）を開く。** 改名（F-03）も削除（F-04）もその中で行う。**追加した列にのみ表示**し、デフォルト3列には出さない。**リスト名の左端**に置く。**編集モード中にだけ出す**（1.2） |
| **`[+ リスト追加]`** | 列の追加（F-02）。**盤面の右端**に置き、押して入力すると**「完了」の左隣**に列が増える。**編集モード中にだけ出す**（1.2） |
| **`[ リストを編集する ]`** | 編集モード（F-24）の出入り口。**ボードの見出しの横**に置く（1.2） |
| **リスト名** | **1行に固定し、折り返さない。** 列幅に収まらない分は**末尾を `…` で省略**する。**マウスでホバーするとフルネームを出す**（`title`）。**見た目はブラウザと OS が決めるため指定しない**（大きさを変えるには自前で描くことになり、仕組みごとの置き換えになる）。**キーボードで見えるようにはしない** — 全文は編集アイコンの読み上げ名と、そこから開くモーダルの入力欄で読める。そのためだけにツールチップを作ると、**列ごとに Tab の停留点が1つ増え**、タスクへ辿り着くまでの操作が列数ぶん長くなる |
| **`[+ タスク追加]`** | **列の最上部。** 押して入力すると、**すぐ下（列の先頭）**にタスクが入る（F-06）。**「完了」列には出さない**（#20）。実際のタスク管理で完了に直接起票する場面がほぼ無く、完了へ入れる手段はドラッグ&ドロップ（F-13）と詳細モーダル（F-23）があるため。**「進行中」や追加した列には出す** — そこへ直接起票したいかの判断は、ブラッシュアップ案（F-22 など）の前提と混ざるため今は決めない |
| **タスクの移動ボタン** | **存在しない。** 移動はドラッグ&ドロップ（F-13）と詳細モーダル（F-23）で行う。F-12 は欠番 |
| `☐` チェックボックス | **どの列のタスクにも出る。****普段はカードの下に隠れており**、ホバーまたはフォーカスで現れる。**意味だけが列によって違う** — 「完了」列では**選択**（F-15。チェックした行はホバーを外しても出たまま）、それ以外の列では**「完了にする」**（F-22。押すとタスクが完了列の先頭へ移るため、チェックは入ったままにならない）。**見せ方を揃えるのは、列によって作法が変わると同じ盤面の中で操作の予測が立たなくなるため** |
| **選択の行** | `[全選択] [選択解除] [〇件を削除]` の3つを1行に。**「完了」列にだけ、常に出す**（#20）。出し分けにすると完了列だけこの行が消え、タスクの開始位置が1行ぶん上がる。**1件も選んでいない間は `[選択解除]` と `[0件を削除]` を押せない状態にする**（確認モーダル1枚で全件削除に到達させないため）。**タスクが0件の列では `[全選択]` も押せない。****枠と余白は他の列の `[+ タスク追加]` と同じ**にすること |
| （タスクなし） | **空状態。** タスクが0件の列に表示する。**ここにもドロップできる** |
| `：` | 図の省略記号（実際の画面には表示しない） |
| **タスク一覧の領域** | **列の中で縦にスクロールする**（F-25）。スクロールするのはここだけで、リスト名と `[+ タスク追加]`（＝選択の行）は**外に置くため隠れない**。**横にはスクロールさせない。** 縦のスクロールバーは細くする |
| **列とカードの幅** | 列は **300px（全列共通）**、カードは **240px 固定で中央寄せ**。左右に 20px ずつ空き、これがチェックボックスの寄り代になる |
| `[削除]`（タスク） | **図では省略している。実物は 2章のとおり**（ゴミ箱アイコンを期限と同じ行の右端に常時表示。2026-08-15 決定）。**ホバー時のみにする案は採らなかった** |

> **盤面はウィンドウの高さに収める。**（F-25）**ページ全体が縦にスクロールすると、ボード名もリスト名も一緒に流れて隠れる。** 列が多いボードでは、どの列に入れようとしているかが分からなくなる。スクロールする範囲を各列のタスク一覧だけに絞れば、見出しは常に見えたままになる。
>
> **リスト名を `position: sticky` で貼り付ける方法は採らない。** 見出しをスクロール領域の外の兄弟要素として置けば、貼り付ける必要がそもそも無い。
>
> **表示件数の上限は設けない。** 見える件数はウィンドウの高さ次第。以前は「9件まで表示し、10件目が上部だけ覗く」（F-14）としていたが取り下げた。経緯は [要件定義書](../requirements.md) の「機能一覧」を参照。

> **チェックボックスを常時表示にしない理由。**（F-15）常に出すと、その幅のぶん**完了列だけカードが狭くなるか、列の幅が他と揃わなくなる。** この画面は列を横に見比べるためのものなので、完了列だけ見た目が変わるのは避けたい。**普段は隠しておき、ホバーかフォーカスで出す。**
>
> **カードは動かさず、と最初は考えたが、場所が足りなかった。** カードの左に空いているのは余白だけで、そこへチェックボックスを出すと列からはみ出す。**カードを右へ 12px 寄せて、空いた左に出す。**
>
> **寄ること自体も選択の合図として使う。** チェックの印だけでなく行の位置でも示すので、**別のウィンドウが重なって見づらいときでも、選ばれている行が分かる。** 複数のウィンドウを開いて重なっている状況は容易に起こりうる。
>
> **ホバーを判定する対象は、動かない外側の入れ物にする。** カードを対象にすると、右へ寄った瞬間にポインタがカードの外に出て判定が切れ、戻ってまた寄る、を繰り返して振動する。
>
> **チェックボックスは列の左端に貼り付けない。** フォーカスの枠はチェックボックスの外側に描かれるため、左端に置くと枠がスクロール領域に切り取られ、**フォーカスが当たっているのに見えない**状態になる。
>
> **選択の行は `[+ タスク追加]` と入れ替える（足さない）。** 行を増やすと完了列だけタスクの先頭が1行ぶん下がり、横に並べたときに揃わなくなる（v1.4 の編集アイコン、v1.6 の並び替えの行と同じ理由）。**入れ替える相手と枠・余白を揃えないと、チェックを入れた瞬間に列の中身が上下してがたつく。**
>
> ~~**1件も選んでいないと選択の行は出ない。**~~ **この記述は撤回する**（#103 で実装との食い違いとして発見）。実装では上の表のとおり**選択の行を完了列に常時表示し、1件も選んでいないあいだはボタンを押せない状態にしている。** 行そのものを出し入れすると、チェックを入れた瞬間に列の中身が上下してがたつくため（1つ上の但し書きと同じ理由で、こちらと両立しなかった）。
>
> **ねらいは変わっていない。** 「全件削除が確認モーダル1枚で到達できるより、まず一手挟む方が誤操作を抑えられる」は、`[全選択]` を押す一手として残っている。

> **`[+ タスク追加]` を最上部に置く理由。** 追加ボタンが上端にあるのに追加物が末尾に現れると、追加したものが視界の外に出る。**タスクが入りきらない列ではスクロールしないと確認できず**、登録できたか分からない。**操作した位置と、結果が現れる位置を一致させる。**
>
> **タスクに移動ボタンを置かない理由。** ボタンが件数分だけ縦に積み上がると、1件あたりの高さが増えて**1画面に収まるタスクが減る**。一覧して状況を把握することがボードの主目的である以上、そこを削ってまで操作手段を増やさない（[機能仕様書](../functional-spec.md) の「タスクの移動・並び替え」を参照）。

### 1.2 リストの編集モード（F-24 ＋ F-21）

**ボード見出しの横の `[ リストを編集する ]` で出入りする。`Esc` でも抜ける。**

```
┌──────────────────────────────────────────────────────────────────────┐
│  マイタスク            [ リストの編集を終える ]  ← 押すか Esc で戻る    │
├──────────────┬──────────────┬──────────────┬───────────┬────────────┐
│[←] TODO  [→] │[←] 進行中 [→] │[←] ✎設計 [→] │           │            │
│              │              │              │  完了      │[+ リスト追加]│
│  ┌────────┐  │  ┌────────┐  │              │ ┌────────┐ │            │
│  │請求書   │  │  │資料作成 │  │（タスクなし）│ │打合せ   │ │            │
│  └────────┘  │  └────────┘  │              │ └────────┘ │            │
│  ┌────────┐  │              │              │            │            │
│  │買い物   │  │              │              │            │            │
│  └────────┘  │              │              │            │            │
└──────────────┴──────────────┴──────────────┴───────────┴────────────┘
   ↑ タスクは見えているが、掴めず・押せず・チェックもできない
     `[+ タスク追加]` と選択の行も出さない
```

**列を掴んで動かしている間は、落ちる位置に縦の線を引く。**

```
┌──────────────┬──────────────┬┬──────────────┬───────────┐
│[←] TODO  [→] │[←] 進行中 [→] ││[←] ✎設計 [→] │  完了      │
│              │              ││              │           │
└──────────────┴──────────────┴┴──────────────┴───────────┘
                               ↑ ここに落ちる
```

| 要素 | 補足 |
| --- | --- |
| **モードの入口** | ボード見出しの横の `[ リストを編集する ]`。**モード中は文言が `[ リストの編集を終える ]` に変わる。** 状態は支援技術にも伝える |
| **`Esc`** | モードを抜ける。**列を掴んでいる最中に押した場合は、移動の取り消しとモードの終了が同時に起きる**（下記） |
| **列の見出し** | `[←] リスト名 [→]` を1行に収め、追加した列には `✎` も出す。**並び替えのための行は取らない** |
| **列を掴む範囲** | **列全体。** 専用のつまみは置かない |
| **落ち先の表示** | **縦の線。** 他の列は動かさない（3章のタスクと同じ考え方） |
| **「完了」列** | **掴めず、`[←] [→]` も出さない。** 常に最右 |
| **タスク** | **見えているが操作できない。** カードのドラッグ・チェック・ゴミ箱・`[+ タスク追加]`・選択の行がすべて止まる |
| **`[+ リスト追加]`** | 盤面の右端。**モード中にだけ出す** |

> **掴んでいる最中の `Esc` は、移動の取り消しとモードの終了が同時に起きる。**（2026-09-01 決定、#101）
>
> **そうしてよい、という判断。** **カーソルで掴んで操作すること自体には問題がない。** その状態で `Esc` を押す——つまり**メインの手段であるカーソル操作を、補助的なキー操作でキャンセルしなければならない状況**であれば、**編集モードごと終了したほうがよい。**
>
> **仕組みとしては、どちらも `Esc` を拾っているために起きる。** dnd-kit は移動を取り消すときに `preventDefault()` を呼ぶが、**イベントの伝播は止めない**ため、モードを抜ける側の処理も続けて動く。**分けることもできる**（[ブラッシュアップ案](../backlog.md) 5章に案を置いた）が、**いまは分けない。**

> **リストへの操作をモードに集約する理由。**（#89）**平時のタスク管理を、視覚的にも操作感的にも邪魔しないため。** リストの追加・改名・削除・並び替えはどれも頻度が低いのに、**列ごとに矢印の行と `✎`、盤面の右端に `[+ リスト追加]`** が常に場所を取っていた。**モード外に残るのがリスト名とタスクだけ**になれば、「リストへの操作はすべてモードの中、モード外はタスク管理だけ」と一言で説明でき、覚えることが1つで済む。

> **v1.6 の2つの判断を取り消す。** ①**「完了列にはボタンを出さないが行の高さは空ける」** — 行そのものを撤去するので、揃える対象が消える ②**「端のボタンは押せない状態で残す」** — これはモード中の話として残す（モード中に列ごとのボタン数が変われば、やはり見出しの位置がずれるため）。**どちらも「矢印を常設する」ことが前提だった。**

> **モード中はタスクの操作をすべて止める。** 列を掴む範囲が列全体なので、その内側のカード・チェック・ゴミ箱と**押したいものが決まらない。** 止めることで「いまはリストを並べる時間」であることも見た目で伝わる。

> **`[+ リスト追加]` もモードの中に入れる。** これだけ外に残すと原則に例外が1つできる。**デフォルトの3列は必ず存在する**ので、モードに入らないとボードが空のまま、ということは起きない。

## 2. タスク（拡大）

```
 ┏━━━━━━━━━━━━━━━━━━━━┓  ← 期限による色付きボーダー（F-11）
 ┃ 請求書送付            ┃  ← タイトル（ただの文字）
 ┃ 08/10 09:00      [🗑] ┃  ← 期限とゴミ箱を同じ行に。ゴミ箱は右端
 ┗━━━━━━━━━━━━━━━━━━━━┛     カード全体：クリックで詳細モーダル、
                              掴んでドラッグすると移動する

 期限がない場合も行の高さは変えない
 ┏━━━━━━━━━━━━━━━━━━━━┓
 ┃ 読みたい本を探す      ┃
 ┃                  [🗑] ┃  ← 期限の位置は空けたまま
 ┗━━━━━━━━━━━━━━━━━━━━┛
```

一覧に表示するのは**タイトルと期限のみ**。説明文は表示しない。

| 要素 | 補足 |
| --- | --- |
| **カード全体** | **詳細モーダルを開く（F-07）。** クリック、またはフォーカスして `Enter`。**掴んで動かすのは `Space`**（F-13）。以前はタイトルだけを押せるようにしていたが、**カードそのものが既にボタンだった**ため停留点が二重になっていた（下記） |
| **タイトル** | **ただの文字。** 押せる要素にはしない |
| ゴミ箱アイコン | **削除（F-08）。** 「削除」の文字ボタンにはしない。**常時表示**とし、ホバー時のみにはしない。**押してもカードの詳細は開かない**（クリックをカードへ伝えない） |
| 配置 | **期限と同じ行の右端。** 削除のためだけに行を増やさない |
| 色 | **タスクの文字色に追従させる。** 期限超過・当日（白文字）でも完了列（黒文字）でも判別できること |
| 期限なしの場合 | **行の高さは揃える。** 期限の有無で高さが変わると縦の並びがばらつく |

> **掴んでいる間は、盤面のどこも更新できない。**（2026-09-01、#97）カードの詳細も、チェックボックスも、ゴミ箱も、`[＋ タスク追加]` も、列の `[←] [→]`・編集アイコン・`[＋ リスト追加]` も、**運んでいる最中は反応しない。** 移動の途中に別の更新が挟まると、何がどこへ動いたのかが利用者にも追えなくなる。
>
> **キーボードで掴んでいるときに効いてくる。** マウスのドラッグと違い、**掴んだままポインタが自由に動く**ので、掴んだカード以外を押せてしまう。**掴んだカードは元の位置に透明で残っている**（場所を空けておくため）ので、そこも押せてしまっていた。
>
> **ポインタとキーボードの両方を塞ぐ必要がある。** カードの上は `pointer-events` で止まるが、**キーボードのフォーカスはそれでは止まらない。**

> **開く操作をカード全体に移した理由。**（2026-08-31、#95）**Tab の停留点を減らすため。** ドラッグを入れた時点（F-13）から、カード本体には `role="button"` と `tabindex` が付いている（掴む操作をキーボードでも行うために要る）。そこにタイトルのボタンが加わり、**タスク1件につき停留点が4つ**（チェックボックス・カード本体・タイトル・ゴミ箱）、**うち2つは読み上げ名まで同じ**という状態になっていた。20件の列なら80回。**タイトルのボタンを外して3つにした。**
>
> **キーは `Enter`（開く）と `Space`（掴む）で分ける。** dnd-kit の既定では `Enter` も掴む側だが、そちらを `Space` だけに絞った。**マウスのドラッグとも競合しない** — 掴み始めるのに 5px の移動を要るようにしてあるので、動かさずに離せばクリックとして扱われる。
>
> **専用のドラッグのつまみは置かない。** 停留点は減らないうえ、**カード全体を掴める使い勝手を失う。**

> **アイコンは実装側の図形描画で作る。** 画像ファイルは持たない。絵文字（🗑）も使わない — フォントによって字形も色も変わり、文字色への追従ができないため。**上図の `🗑` は図中での便宜的な表記**であり、実装に絵文字を使う意味ではない。

## 3. ドラッグ中の表示（F-13）

**どこに落ちるかを、指を離す前に分かるようにする。** 落ちた場所が予想と違うと、利用者は毎回結果を確認してからやり直すことになる。

```
   移動元                        移動先（「進行中」列）
 ┌──────────────┐            ┌──────────────┐
 │ [+ タスク追加]│            │ [+ タスク追加]│
 │ ┌──────────┐ │            │ ┌──────────┐ │
 │ │ 資料作成  │ │            │ │ 資料作成  │ │
 │ └──────────┘ │            │ └──────────┘ │
 │              │            │ ━━━━━━━━━━━━ │ ← 挿入位置を示す線
 │              │ …掴まれた   │ ┌──────────┐ │
 │              │   元の位置  │ │ 打合せ    │ │
 │              │  （空ける） │ └──────────┘ │
 └──────────────┘            └──────────────┘

                  ┏━━━━━━━━━━┓
                  ┃ 請求書送付 ┃ ← ポインタに追従する本体
                  ┃ 08/10 09:00┃
                  ┗━━━━━━━━━━┛
```

| 要素 | 仕様 |
| --- | --- |
| 掴まれたタスクの元の位置 | **透明にして場所だけ残す。** カードは描かないが、幅も高さもそのまま空ける |
| ポインタに追従する本体 | 掴んでいるタスクの見た目を保つ。**盤面の外側に描き、列のスクロール領域には切り取らせない** |
| **挿入位置の線** | ポインタのY座標が、どのタスクの前後に入るかを示す。**列をまたいでも同様に出す** |
| 落ちる位置以外の見せ方 | **他のカードは動かさない。** 落ち先は線だけで示す |
| 空状態の列 | 「（タスクなし）」の領域全体が受け口になる |
| スクロールする列 | **スクロール位置はそのままドロップを受け付ける。** 落としたい位置が見えていない場合は、**掴む前にその列をスクロールしておく**（F-25）。ドラッグ中に端で自動スクロールする仕組みは持たない |
| ドロップ範囲の外で離した場合 | 移動しない。元の位置に戻る |

> **掴まれた元の位置を、薄く残すのではなく透明にした理由。**（2026-08-30、#78）
> v1.8 までは「薄く表示し、まだそこに属していることを示す」としていた。実装して触ったところ、**ポインタに追従する本体と同じカードが2枚見える**状態になり、目は動いている本体の方を追うため、薄い方が情報として働いていなかった。
>
> **消さずに場所を空けるのが要点。** 消すと並びが詰まり、掴んだ瞬間に列全体が動く。透明なら幅も高さもそのままなので、空いた場所が「ここから出ていく」という予約として読める。

> **落ち先を線だけで示す理由。**（2026-08-30、#78）
> 「他のカードが動いて隙間が空く」見せ方と併用しない。**示し方が二重になって読みにくい**うえ、**列をまたぐと隙間は原理的に出ない**（並び替えの範囲が列ごとに別々のため）。線に一本化すれば、同じ列でも別の列でも見え方が揃う。
>
> **落ち先はポインタのY座標で決める**（この表の「挿入位置の線」のとおり）。カードの中線より上ならそのカードの手前、どの中線にも届かなければ末尾。**ライブラリが持つ距離ベースの判定は使わない** — 受け口の重心や四隅との近さで選ぶため、列と列の間の余白でいちばん近い列が選ばれ、カードとカードの隙間では列そのものが選ばれて末尾へ飛ぶ。
>
> **キーボード操作のときだけ距離で決める。** 掴んで矢印で動かす操作にポインタは存在しないため。線はどちらの操作でも出る。

> **キーボードでの動かし方。**（2026-09-01、#97）**`↑` `↓` は同じ列の中だけを動き、`←` `→` で列をまたぐ。**
>
> | 項目 | 決めたこと |
> | --- | --- |
> | 置ける場所 | **元いた列ではカードの数だけ。** 自分がいまいる場所も1つに数え、**いちばん下の場所へ動かすことが「末尾に入れる」** |
> | 別の列では | **カードの数より1つ多い。** 自分はまだそこに居ないので、最後のカードの後ろが増える |
> | 端では | **動かない。** 一番上で `↑`、一番下で `↓` を押しても何も起きない |
>
> **ライブラリ任せにはできない。** dnd-kit の標準の計算は**登録されている受け口をすべて候補にし、押した向きと距離だけで選ぶ**ので、**列を区別しない。** 2件の列の一番下から `↓` を押すと、**4件ある列の3番目**が選ばれる。**「いま乗っている列」を見て、その中の場所を順に移る**形にしてある。
>
> **「いま乗っている列」と「元いた列」を取り違えないこと。** 盤面は落とすまで変わらないので、データ上そのタスクはずっと元の列にいる。ここを混同すると、**別の列で元の列の行数ぶん下がる・一番上に置けない・元いた列へ戻れない**といった形で現れる。

## 4. タスクの詳細モーダル（F-07, F-23）

**タスクのカードをクリックすると開く。** キーボードではカードにフォーカスして `Enter`（2章）。

```
      ┌────────────────────────────────────────────┐
      │ タスクの詳細                          [ ✕ ] │
      ├────────────────────────────────────────────┤
      │ ステータス  ┌──────────────────┐            │  ← 移動先を選ぶ（F-23）
      │             │ TODO           ▼ │            │     ラベルと欄は同じ行
      │             └──────────────────┘            │
      │                                            │
      │ タイトル                                    │
      │ ┌────────────────────────────────────────┐ │
      │ │ 請求書送付                              │ │
      │ └────────────────────────────────────────┘ │
      │                                      5/100 │  ← 文字数カウンタ
      │                                            │
      │ 説明文                                      │
      │ ┌────────────────────────────────────────┐ │
      │ │ 8月分の請求書をまとめて送付する。        │ │
      │ │                                        │ │  ← 改行を保持
      │ │ ・A社                                   │ │
      │ │ ・B社                                   │ │
      │ │                                        │ │
      │ └────────────────────────────────────────┘ │
      │                                   348/5000 │
      │                                            │
      │ 期限                    ☑ 時刻も指定する    │  ← ラベルと同じ行
      │ ┌──────────────┐ ┌────────┐ ┌───────────┐ │
      │ │ 2026/08/10   │ │ 09:00  │ │ 期限をクリア│ │  ← 3つとも同じ行
      │ └──────────────┘ └────────┘ └───────────┘ │
      │                                            │
      ├────────────────────────────────────────────┤
      │                    [ キャンセル ] [ 保存 ] │
      └────────────────────────────────────────────┘
```

| 要素 | 補足 |
| --- | --- |
| **`ステータス` の選択欄** | **F-23。** 現在の所属リストを表示し、変更して `[ 保存 ]` すると**そのリストの末尾へ移動する**。選択肢は「完了」を含む全リスト |
| 文字数カウンタ | 入力欄の右下。上限到達で赤 |
| `☑ 時刻も指定する` | **`cards.has_due_time` に対応。** 外すと時分の入力欄が無効になり、表示からも時分が消える |
| `[ 期限をクリア ]` | `due_at` を NULL に戻す（期限なし） |
| 閉じ方 | `[ ✕ ]`、`[ キャンセル ]`、背景クリック、**`Esc`** のいずれか |
| **初期フォーカス** | **説明文の入力欄。キャレットは末尾に置く。** 開いてすぐ書き足せる状態にするため。タイトルは既に埋まっていることが多く、説明文こそ追記の対象になる |

> **この欄だけ「リスト」ではなく「ステータス」と呼ぶ**（#38 で決定）。盤面では列を「リスト」と呼んでいるが、**ここで選ぶのは「このタスクが今どういう状態か」**であり、入れ物を選んでいる感覚とは違う。呼び分けは意図的なもので、表記ゆれではない。

> **リストの選択欄をタイトルより上に置く理由。** そのタスクが「今どこにあるか」は、内容を読む前に把握したい情報だから。また **`[ 保存 ]` までキーボードのタブ移動だけで到達できる位置**にあることで、マウスを使わない移動操作（F-23 の主目的）が自然な順序になる。

## 6. リストの詳細モーダル（F-03, F-04）

**リストの編集アイコン（1章）から開く。** リスト名の変更と削除をここで行う。**編集アイコンが出るのは編集モード中だけ**なので、**このモーダルへの入口もモードの中にある**（1.2）。

```
      ┌────────────────────────────────────┐
      │ リストの詳細                  [ ✕ ] │
      ├────────────────────────────────────┤
      │ リスト名                            │
      │ ┌────────────────────────────────┐ │
      │ │ 設計・調査                      │ │  ← 現在の名前が入った状態で開く
      │ └────────────────────────────────┘ │
      │                              5/50  │  ← 文字数カウンタ（E-01）
      ├────────────────────────────────────┤
      │ [ このリストを削除 ]                │  ← 赤系。押すと確認モーダル（7章）
      │ 中のタスク 3 件も一緒に削除されます。│  ← 0件なら「中にタスクはありません。」
      ├────────────────────────────────────┤
      │            [ キャンセル ] [ 保存 ] │
      └────────────────────────────────────┘
```

| 要素 | 補足 |
| --- | --- |
| リスト名 | **現在の名前が入った状態**で開く。付け直しではなく手直しになるため。上限50文字 |
| `[ このリストを削除 ]` | **保存とは別の区画に置く。** 並べると押し間違える。押すと確認モーダル（7章）へ進む |
| 件数の注記 | **確認モーダルを開く前に、何が失われるかを見せる。** 0件のときは「中にタスクはありません。」と出す（注記そのものを消さない — 行が消えるとボタンの位置が動く） |
| デフォルト3列 | **そもそも開けない**（編集アイコンを出さない）。サーバーも改名・削除を拒否する |
| 閉じ方 | `[ ✕ ]`、`[ キャンセル ]`、背景クリック、**`Esc`** のいずれか |
| **初期フォーカス** | **リスト名の入力欄**（現在の名前を全選択した状態） |

> **「リスト名の変更」専用のモーダルにしない理由。** 名前1つのためだけのモーダルは操作に対して重く、**使っているうちにその場編集へ寄せたくなり、モーダルごと無くなる。** 一方、リストに対する操作は名前だけではない（削除がある）。**対象を開いて、その状態をまとめて扱う**形にすれば、タスクの詳細モーダル（4章）と作法が揃う。
>
> **削除をこの中に置く理由。** 列の削除は**滅多にやらず、中のタスクごと消える**。列見出しの行にゴミ箱を並べると、滅多に使わないものが常に目に入り、押しやすい位置に居座る。**ひと手間奥に置く方がこの操作に合う。**
>
> **タスクの削除がカード上にある（2章）のとは非対称だが、意図的。** タスクの削除は**日常的で件数が多く**、リストの削除は**稀で影響が大きい。** 頻度と危険度が逆なので、置き場所が違ってよい。
>
> **置き場所ができたことを理由に機能を足さない。** ここに置くのは、リストそのものの状態に関わるものだけ。

## 7. 削除の確認モーダル（F-04, F-08, F-15）

```
      ┌────────────────────────────────────┐
      │ 削除の確認                          │
      ├────────────────────────────────────┤
      │ リスト「設計」を削除します。        │
      │ 中のタスク 3 件も一緒に削除されます。│
      │ この操作は取り消せません。          │
      ├────────────────────────────────────┤
      │          [ キャンセル ] [ 削除する ]│
      └────────────────────────────────────┘
              ↑ 初期フォーカス      ↑ 赤系
```

| 操作 | 文言に含めるもの |
| --- | --- |
| タスクの削除（F-08） | タスク名 |
| リストの削除（F-04） | リスト名 ＋ **道連れになるタスクの件数**（0件なら「中にタスクはありません。」） |
| 完了列の選択削除（F-15） | 選択件数 |

いずれも「この操作は取り消せません」を添える（Undo は対象外のため）。

> **初期フォーカスは「キャンセル」に置く。** 開いた直後に `Enter` を押しても削除されないようにするため。

**閉じ方は `[ キャンセル ]`、背景クリック、`Esc`**（＝どれもキャンセル扱い）。**`[ ✕ ]` は置かない** — 閉じる手段が2つ並ぶと、どちらが「やめる」なのかを一瞬考えることになる。

### 8.2 操作中に失敗した場合

ボードは表示されたまま、画面上部にメッセージを出す。**あわせて画面の表示を操作前の状態に戻す**（ロールバック）。

```
┌───────────────────────────────────────────────────────────────────┐
│ ⚠ データベースに接続できません。                            [ ✕ ] │
│   Docker が起動しているか確認してください。                        │
├───────────────────────────────────────────────────────────────────┤
│  マイタスク                                                        │
├──────────────┬──────────────┬──────────────┬─────────────────────┤
│ [←] TODO [→] │ [←] 進行中[→]│ [←] 設計 [→] │ 完了                │
│              （ボードはそのまま表示され、操作を続けられる）          │
└──────────────┴──────────────┴──────────────┴─────────────────────┘
```
