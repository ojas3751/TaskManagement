## 1. 進め方の原則

**1ステップごとに必ずブラウザで動作を確認し、コミットする。まとめて作らない。**

## 2. 実装ステップ

| Step | 内容 | 完了の目安 |
| --- | --- | --- |
| 0 | 開発環境のセットアップ | ブラウザに画面が表示される |
| 1 | **DB構築**（Docker、スキーマ、マイグレーション、seed） | `psql` で3列が確認できる |
| 2 | デフォルト3列の表示（F-01） | **DBから取得して表示する** |
| 3 | タスクの追加（F-06, F-16） | リロードしても残る。**追加ボタンは列の最上部、新規タスクはその直下に入る** |
| 4 | タスクの詳細ポップアップ・削除（F-07, F-08） | 説明文の改行保持もここで |
| 5 | 期限の入力・表示ルール（F-09, F-10） | ゼロ埋め、時分なし、年の出し分けまで |
| 6 | 期限の色分け（F-11） | コントラスト比を実測して色を確定する |
| 7 | 文字数カウンタと通信エラー表示（E-01〜E-05） | サーバーを止めて動作を確認する |
| 8 | ボタンでのタスク移動（F-12） | **position の再採番はここで実装する。UC-02・UC-03 が通る。この時点で実用的に使える** |
| 9 | 列の追加・改名・削除・並び替え（F-02〜F-05） | 完了列の固定もここで。UC-05 が通る |
| 10 | 完了列の件数制限と選択削除（F-14, F-15） | アコーディオンの見せ方。UC-04 が通る |
| 11 | タスクのドラッグ&ドロップ（F-13）**＋ 移動ボタンの撤去（F-12 の廃止）** | 最難関。ライブラリを使う。**ドラッグだけで UC-02・UC-03 が通り、移動ボタンが画面から消えていること。ここで MVP 完成** |

## 3. 順序の根拠

| 判断 | 理由 |
| --- | --- |
| **Step 1（DB構築）を先頭に置く** | DB とバックエンドが土台であり、後から差し込むと画面側の作り直しが発生する |
| **「永続化」の独立した Step を設けない** | DB を先に作る構成では、Step 1〜3 の時点で最初から永続化された状態になる。LocalStorage 方式のときは独立した Step が必要だった |
| **Step 8 で実用ラインに到達させる** | タスクの追加・編集・削除・移動が揃えば、自分の実データを入れて使い始められる。使い始めると開発が続きやすい |
| **ドラッグ&ドロップを最後に回す** | 最も実装が難しく、ボタン操作（F-12）で機能としては代替できるため。Step 8 で再採番のロジックを作っておけば、Step 11 は**入力手段の差し替え**で済む |
| **Step 11 で移動ボタンを撤去する** | **F-12 と F-13 は併存させない。** 移動ボタンが全タスクに常時並ぶとボードの閲覧性が落ちるため、ドラッグ&ドロップが動いた時点で取り除く。F-12 は「実装順序のための足場」であり、完成版には残らない（[要件定義書](requirements.md) の「機能一覧」の注記を参照） |

## 4. Step ごとの補足

| Step | 補足 |
| --- | --- |
| 0〜1 | **完了時点で、起動手順を [運用手順](operations.md) に記載すること**（UC-01） |
| 6 | 色コードはここで確定する。純粋な赤に白文字ではコントラスト比 4.5:1 を満たさないため、実測が必要 |
| 7 | 通信エラーの確認には、意図的にサーバーや Docker を停止する必要がある |
| 8 | `position` の再採番は [データベース設計](design/database.md) の「position の採番方式」に従う |
| 10 | 「10件目が上部だけ覗く」高さは、実際にタスクを並べないと決められない |
| 11 | **移動ボタンの撤去とあわせて、削除ボタンの出し方を決める**（常時表示・ホバー時のみ・詳細モーダル内へ移動）。[要件定義書](requirements.md) の「未決定事項」に挙げている |

## 5. ブランチ運用

**都度ブランチを切る運用はしない。** 学習段階では分岐が増えすぎて把握しづらくなるため、原則 `main` に直接コミットする。

以下の場面では、必要に応じてブランチを切る。

| 場面 | 理由 |
| --- | --- |
| Step 11（ドラッグ&ドロップ） | 最難関で、失敗したら丸ごと捨てたくなる可能性がある。**移動ボタンの撤去も同時に行うため、失敗すると操作手段が両方失われる。ブランチを切ることを推奨する** |
| 技術スタックの選び直し | 一度作った構成を大きく作り替えるとき |
| 動いている状態を壊す変更 | Step 8 以降は実用できる状態のため、壊さずに試したい場面が出てくる |
