# タスク管理アプリ 要件定義書（ドラフト v0.2）

作成日: 2026-08-12 / 最終更新: 2026-08-12
ステータス: ドラフト（技術スタック未定 / 要確認事項あり）

---

## 1. 目的と利用者

| 項目 | 内容 |
| --- | --- |
| 目的 | 自分の日々のタスクを Trello 風のボードで管理する |
| 副次目的 | Web 開発の学習、および要件定義など上流工程の実践 |
| 利用者 | 本人1名のみ |
| 利用端末 | PC のブラウザ |

### この前提から確定した「作らないもの」

利用者を1名・端末をPCのみと決めたことで、以下が要件から外れる。

| 除外するもの | 理由 |
| --- | --- |
| ログイン / ユーザー登録 / 権限管理 | 利用者が本人1名のみのため不要 |
| 複数人でのリアルタイム共同編集 | 同上 |
| 端末間のデータ同期 | 利用端末が PC ブラウザのみのため不要 |
| スマホ向けレイアウト対応 | 同上 |
| ファイル添付 / メール通知 | 目的に対して不要 |
| 優先度の設定 | カードのタイトルの付け方で代替できるため不要 |
| ソート機能（期限順・作成日順） | 手動の並び順と競合するため。手動並び替えのみとする |

## 2. 用語と画面構造

```
ボード (Board)    … 一番外側の入れ物。1個のみ
 └ リスト (List)   … 縦の列
    └ カード (Card) … タスク1件
```

画面イメージ:

```

│ ← TODO →    │ ← 進行中 →   │ 完了                  │
```

## 3. リスト（列）の仕様

### 3.1 デフォルトの3列

初回起動時、以下の3列が用意される。

| 列名 | 削除 | 名前変更 | 並び替え |
| --- | --- | --- | --- |
| TODO | 不可 | 不可 | 可 |
| 進行中 | 不可 | 不可 | 可 |
| **完了** | 不可 | 不可 | **不可（常に最右に固定）** |

削除・改名は、UI 上ボタン自体を表示しない。

### 3.2 ユーザーが追加した列

- 追加・名前変更・削除がすべて可能
- 削除時は確認ダイアログを出し、中のカードも一緒に削除される
- **新規追加した列は「完了」の左隣に挿入される**

### 3.3 列の並び替え

タスクの流れは「完了より手前の工程が増える」ことが多いため、列の順番を後から変更できるようにする。

- 「完了」を除く全ての列を、左右に並び替えできる
- 「完了」より右へは移動できない（完了は常に最右）

並び替えの操作は、カードと揃えて **「← →」ボタン**で行う。列のドラッグ&ドロップは MVP に含めず、F-21 として後から追加する。

### 3.4 「完了」列の特別扱い

| 項目 | 仕様 |
| --- | --- |
| 初期表示件数 | **9件**（新しいものから） |
| 10件目以降 | アコーディオンで折りたたむ。**10件目のカードが上部だけ覗いて見える**高さにし、続きがあることを視覚的に示す |
| 展開 | 「もっと見る」で全件表示、再度押すと9件に戻る |
| 選択削除 | 各カードにチェックボックス。「選択したものを削除」でまとめて削除（確認ダイアログあり） |
| 全選択 | 「すべて選択」のチェックボックスを用意し、これで全件削除を代替する |

なお、チェックボックスは **「完了」列のカードにのみ**表示する（他の列には出さない）。

## 4. カード（タスク）の仕様

### 4.1 持たせる情報

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| タイトル | 必須 | タスク名 |
| 説明文（メモ） | 任意 | 詳細ポップアップで閲覧・編集。一覧には表示しない |
| 期限 | 任意 | 年月日は必須、時分は任意（4.3 参照） |
| 作成日時 | 自動 | 自動で記録 |

### 4.2 リスト内でのカードの表示

一覧に表示するのは **タイトル と 期限** の2つのみ。説明文は表示しない。

### 4.3 期限の入力ルール

- 期限を設定する場合、**年月日は必須**
- **時分は任意**。入力しなくてもよい
- 時分が入力されなかった場合、内部的には **00:00** として扱う（入力欄の初期値を 00:00 にしてもよい）

### 4.4 期限の表示ルール

| 条件 | 表示 |
| --- | --- |
| 時分が未入力 | 時分を表示しない（例: `8/20`） |
| 時分が入力済み | 時分まで表示（例: `8/20 15:00`） |
| 期限の年が今年と異なる | 年を表示（例: `2027/1/5`） |
| 期限の年が今年と同じ | 年を表示しない（例: `8/20`） |
| 期限が未設定 | 何も表示しない |

### 4.5 期限による色分け

色は **太めの色付きボーダーでカードを囲う**ことで表現する。

| 期限までの残り | ボーダー | 背景 | 文字色 |
| --- | --- | --- | --- |
| 期限超過 | 太い赤 | **赤** | **白** |
| 当日 | 太い赤 | **赤** | **白** |
| 翌日 | 太い赤 | 通常 | 通常 |
| 2〜3日以内 | 太い黄 | 通常 | 通常 |
| 4日以降 / 期限なし | 通常 | 通常 | 通常 |

背景が赤になるのは「当日および期限超過」のみ。その場合、コントラスト確保のため文字色を白にする。

**判定は「時刻」単位で行う。** 現在日時と期限日時を比較し、期限日時を過ぎていれば「期限超過」とする。時分が未入力のカードは 00:00 として扱われるため、当日中は常に「期限超過」と判定されるが、表示は「当日」と同一（赤ボーダー＋赤背景＋白文字）のため見た目の差は出ない。

### 4.5.1 「完了」列での上書き

「完了」列にあるカードは、期限に関わらず以下の見た目に統一する（終わったタスクを警告する意味がないため）。

| ボーダー | 背景 | 文字色 |
| --- | --- | --- |
| 薄いグレー | 薄いグレー | 黒 |

### 4.6 カードの詳細表示

カードをクリックすると **ポップアップ（モーダル）** が開く。

- 説明文が長くても読みやすいよう、十分な幅と高さを確保する
- ポップアップ内でタイトル・説明文・期限を編集して保存できる
- 背景クリックまたは閉じるボタンで閉じる

## 5. カードの移動・並び替え

2つの操作方法を両方用意する。

| 方法 | 内容 |
| --- | --- |
| ドラッグ&ドロップ | 別の列へ、また列内の任意の位置へ移動する |
| ボタン操作 | 「↑ ↓ ← →」。↑↓は列内での上下移動、←→は隣の列への移動 |

ボタン操作を用意する理由は、ドラッグ&ドロップの実装が最も難しいため、先にボタン版で全体を完成させ、後からドラッグ&ドロップを足せるようにするため。

**自動ソート機能は実装しない**（対象外）。並び順はすべて手動で決める。

## 6. データ構造

```
Board {
  id: string
  title: string
  lists: List[]
}

List {
  id: string
  title: string
  isDefault: boolean   // true なら削除・改名不可（TODO/進行中/完了）
  isFixedLast: boolean // true なら常に最右に固定（完了のみ）
  order: number        // 列の左からの並び順
  cards: Card[]
}

Card {
  id: string
  title: string
  description: string
  dueDate: string | null   // "2026-08-20T15:00" 形式。時分未入力なら "T00:00"。期限なしは null
  hasDueTime: boolean      // 時分が入力されたか。false なら表示時に時分を出さない
  createdAt: string        // 作成日時。自動記録
  order: number            // 列内の上からの並び順
  isSelected: boolean      // 完了列での一括削除の選択状態（画面上の状態）
}
```

**設計メモ**

- `id` は重複しない文字列。移動・削除の対象特定に使う
- `order` を明示的に数値で持つ。配列の順番に頼ると並び替えで破綻しやすい
- `isDefault` で3列の保護、`isFixedLast` で完了列の位置固定を表現する。UI 側はこのフラグを見てボタンを出し分ける
- `dueDate` は常に時分まで持ち（未入力なら 00:00）、色分けの判定に使う。表示するかどうかは `hasDueTime` で切り替える。「00:00 が未入力なのか、本当に 0 時指定なのか」を区別するためにフラグを分けている
- `createdAt` は MVP では使わないが、後から必要になったときに遡れないため最初から記録しておく

---

## 7. データの保存

- ブラウザ内に保存し、リロード・PC再起動後も内容が残ること
- サーバー・データベースは使わない
- バックアップ機能（ファイルへの書き出し・読み込み）は MVP に含めない

---

## 8. 誤操作への対策

削除操作（カード削除・列削除・完了列の選択削除）の前に確認ダイアログを出す。
Undo（元に戻す）機能は実装しない。

## 9. 機能一覧と受け入れ条件

### 9.1 MVP（これが全部動けば完成）

| ID | 機能 | 受け入れ条件 |
| --- | --- | --- |
| F-01 | 初期表示 | 初回起動で TODO / 進行中 / 完了 の3列が表示される |
| F-02 | 列の追加 | 「+ リスト追加」で名前を入力すると、**「完了」の左隣**に列が増える |
| F-03 | 列の名前変更 | 追加した列は改名できる。デフォルト3列には改名ボタンが出ない |
| F-04 | 列の削除 | 追加した列は確認後に削除できる。デフォルト3列には削除ボタンが出ない |
| F-05 | 列の並び替え | 「完了」以外の列を左右に動かせる。「完了」より右へは移動できず、完了自身も動かせない |
| F-06 | カードの追加 | 各列の「+ カード追加」でタイトルを入力すると末尾に追加される |
| F-07 | カードの詳細ポップアップ | カードをクリックするとポップアップが開き、タイトル・説明文・期限を編集して保存できる |
| F-08 | カードの削除 | 確認ダイアログの後に削除される |
| F-09 | 期限の入力 | 年月日は必須、時分は任意で入力できる |
| F-10 | 期限の表示 | 時分なしは時分を出さない。今年と異なる年のときだけ年を表示する |
| F-11 | 期限の色分け | 期限超過・当日は赤ボーダー＋赤背景＋白文字、翌日は赤ボーダー、2〜3日以内は黄ボーダーになる。完了列のカードは期限に関わらず薄いグレー＋黒文字になる |
| F-12 | ボタンでのカード移動 | ↑↓で列内、←→で隣の列へ移動する。端では該当ボタンが無効になる |
| F-13 | カードのドラッグ&ドロップ | 別の列・列内の任意の位置へドラッグして移動できる |
| F-14 | 完了列の件数制限 | 完了列は9件まで表示し、10件目が上部だけ覗いて見える。「もっと見る」で全件展開できる |
| F-15 | 完了カードの選択削除 | チェックしたカードを確認後にまとめて削除できる。全選択も可能 |
| F-16 | データの永続化 | リロード・ブラウザ再起動後も内容が保持される |

### 9.2 MVP 後に追加する

| ID | 機能 |
| --- | --- |
| F-17 | ラベル（色タグ） |
| F-18 | カードの検索・絞り込み |
| F-19 | ボードの複数管理 |
| F-20 | データのバックアップ（書き出し・読み込み） |
| F-21 | 列のドラッグ&ドロップ並び替え（F-05 のボタン操作を補完する） |

### 9.3 対象外

ログイン、複数人共同編集、サーバー保存、スマホ対応、ファイル添付、通知、Undo、優先度、自動ソート。

## 10. 開発の進め方

1ステップごとに必ずブラウザで動作を確認し、コミットする。まとめて作らない。

| Step | 内容 | 完了の目安 |
| --- | --- | --- |
| 0 | 開発環境のセットアップ | ブラウザに画面が表示される |
| 1 | デフォルト3列を表示（F-01） | データはコードに直書き。見た目のみ |
| 2 | カードの追加（F-06） | リロードで消えてよい |
| 3 | データの永続化（F-16） | リロードしても残る |
| 4 | カードの詳細ポップアップ・削除（F-07, F-08） | 説明文と期限の編集もここで |
| 5 | 期限の入力・表示ルール（F-09, F-10） | 時分なし、年の出し分けまで |
| 6 | 期限の色分け（F-11） | ボーダー・背景・文字色 |
| 7 | ボタンでのカード移動（F-12） | この時点で実用的に使える |
| 8 | 列の追加・改名・削除・並び替え（F-02〜F-05） | 完了列の固定もここで |
| 9 | 完了列の件数制限と選択削除（F-14, F-15） | アコーディオンの見せ方 |
| 10 | カードのドラッグ&ドロップ（F-13） | 最難関。ライブラリを使う。**ここで MVP 完成** |

> Step 3 の永続化を早い段階に置いているのは、自分の実データを入れて使い始められると開発が続きやすいため。
