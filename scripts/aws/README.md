# scripts/aws（作業の始めと終わりに使うスクリプト）

AWS の上で作業するときの、**始め**と**終わり**の手順をまとめたスクリプト。DB のデータを S3 に退避・復元する。

| スクリプト | いつ使うか | やること |
| --- | --- | --- |
| [start.ps1](start.ps1) | 作業の始め | `terraform apply` → サーバーの準備を待つ → S3 のバックアップから DB を復元 |
| [stop.ps1](stop.ps1) | 作業の終わり | DB を S3 に退避 → **退避がすべて成功したときだけ** `terraform destroy` |

```powershell
pwsh scripts/aws/start.ps1   # 作業の始め（ここから従量課金）
pwsh scripts/aws/stop.ps1    # 作業の終わり
```

リポジトリのいちばん上のフォルダで実行する。どちらも、作業者の鍵（プロファイル `taskmgmt`）を使う。apply / destroy の前に、いつもどおり一覧が表示されるので、読んでから `yes` と入力する。

> **`terraform destroy` を直接打たないこと。** 退避されずに DB が消え、データが失われる。作業の終わりは必ず `stop.ps1` を使う。

---

## 最初に1回だけやること

バックアップの置き場（S3 バケット）を作る。作業のたびに消すものとは別の Terraform（`infra/persistent`）で管理しているので、`stop.ps1` で消えることはない。

```powershell
$env:AWS_PROFILE = "taskmgmt"
terraform -chdir=infra/persistent init
terraform -chdir=infra/persistent apply
```

料金は置いた量だけ（数 MB で月 $0.001 未満）。作った後、`infra` 側でも `terraform -chdir=infra init` を一度やり直す。

## 中で何をしているか

EC2 の中で動く手順は [remote/](remote/) にある。PC のスクリプトが、AWS の Run Command（EC2 に命令を送る仕組み。EC2 に使う分は無料）で送って実行させる。サーバーに入って手で打つ必要はない。

### 退避（stop.ps1 → remote/backup.sh）

1. 今の DB の、表ごとの件数を数える
2. **前回のバックアップと件数を比べる。前回1件以上あった表が 0 件になっていたら止めて、確認を求める**（復元に失敗した空の DB を退避して、良いバックアップを押し出さないため）
3. `pg_dump` で DB の中身をファイルに書き出す
4. `pg_restore --list` で、そのファイルが読めるか検査する
5. S3 に置く（S3 がチェックサムで中身を照らし合わせ、壊れていたら受け取らない）
6. S3 に置いた版の大きさとチェックサムが、手元と一致するか確かめる

1〜6 がすべて成功したときだけ、destroy に進む。

### 復元（start.ps1 → remote/restore.sh）

1. **DB に表が1つでもあれば、何もしない**（既にあるデータを壊さない）
2. バックアップがまだ無ければ、空の DB のまま始める
3. 退避したときに記録した版を取り出し、チェックサムを照らし合わせる
4. `pg_restore` で書き戻す。**1つのトランザクションで行うので、途中で失敗したら何も書き戻さなかったことになる**
5. 表ごとの件数が、退避したときと一致するか確かめる

アプリ（段階 3）は、必ず復元の後に起動する。先に起動すると、Flyway が空の DB に初期データを入れてしまい、1 の確認で復元できなくなる。

### 2世代の残し方

S3 では、いつも同じ名前（`backups/latest.dump`）で上書きする。バケットの版の管理（バージョニング）で「1つ前の版」が残り、それより古い版は S3 が自動で消す（`infra/persistent/main.tf`）。古くなってから1日以上たった版が消える対象なので、1日に何度も退避した日は、一時的に3世代以上残る。

## 困ったとき

| 表示 | 意味と対処 |
| --- | --- |
| `BACKUP_BLOCKED`（退避が止まった） | 前回はデータがあった表が 0 件になっている。自分で全部消したなど、正しい場合だけ `YES` と入力して続ける。分からなければ中止する（destroy はされず、データは DB に残る） |
| 「サーバー（EC2）がありません」 | 1時間何もしなかったため、アラームでサーバーが終了した。DB は残っているので、`start.ps1` でサーバーを作り直してから（DB にデータがあるので復元はされない）、もう一度 `stop.ps1` |
| 「DB に既にデータがあるので、復元しませんでした」 | 前回の DB が残っていた（上の場合など）。そのまま使ってよい |
| 退避・復元が失敗した | destroy はされない。表示を読み、分からなければ AI に表示を見せる |
